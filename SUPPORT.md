# Support

## Where to get help

- **Documentation**: start with [spec.md](spec.md) and the `docs/`
  directory. The specification is normative and written for humans.
- **Bugs**: open an issue with the **Bug report** form. Reproduction
  steps and version information get the fastest responses.
- **Features and changes to the standard**: open an issue with the
  **Feature request** form. Major design decisions require an ADR or
  spec.md text before implementation (see `docs/decisions/`).
- **Maintenance and scoped work**: use the **Task** form.
- **Security**: do NOT open an issue, and do not use the **Security
  report** form for an exploitable vulnerability. Use the private path
  in [SECURITY.md](SECURITY.md) (repository → Security → Report a
  vulnerability).

## Expectations

RepoForge is an open-source project maintained on a best-effort
basis. There is no SLA and no guaranteed response time. Scoped,
well-described requests move fastest.

## Never include

Tokens, credentials, or private repository data in any issue, log, or
screenshot. `repoforge` output is designed to be safe to paste; if
it ever leaks a token, that is a critical bug — report it per
SECURITY.md.
